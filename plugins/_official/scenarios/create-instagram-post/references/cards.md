# Картки-сторінки

Картка — екран, документ або число, намальовані **розміткою**, а не
моделлю. Живуть у `assets/blocks/<id>.html`, пишуться агентом.

## Коли картка, а коли стікер

| Про що фраза | Що ставимо |
|---|---|
| предмет, метафора, дійова особа | стікер |
| інтерфейс: вікно, термінал, файл, чат | **картка** |
| перелік, кроки, порівняння | **картка** |
| число, яке має вирости | **картка** |
| службова звʼязка, повтор, висновок | нічого |

Правило коротко: **згенерована картинка терміналу дає розмитий мультик**,
де текст не читається й не масштабується. Та сама картка розміткою дає
справжній моноширинний рядок, чіткий на будь-якому кеглі, — і головне,
її рядки можуть відкриватись ПІД МОВУ, чого растр не вміє в принципі.

**Чергування обовʼязкове.** Три стікерні сцени поспіль — і кадр
одноманітний; три картки поспіль — і ролик перетворюється на презентацію.
Приблизно кожна третя-четверта сцена має бути карткою.

## Три договори студії

Студія знає про картку рівно три речі: коли показати, скільки тримати і
як вести час. Вигляд вирішує сама картка.

**`data-reveal`** — елементи відкриваються по черзі під мову, студія
додає їм клас `is-shown`. Закритий і відкритий стан описує CSS картки.

**`data-progress`** — на елемент приходять дві змінні: `--p` (рівний хід
0→1) і `--pe` (з гальмуванням). Що з ними робити — ширина смуги, кут,
прозорість — вирішує картка:

```css
.bar i { width: calc(var(--pe) * 100%); }
```

`--pe` для завантажень і заповнень: справжнє завантаження доповзає
останні відсотки помітно довше, і саме це читається як завантаження, а
не як рівний повзунок.

**`data-count`** — число росте само. `data-count="100"` — до чого,
`data-count-from` — від чого (типово 0), `data-count-suffix` — що
дописати («%», « КБ»), `data-count-decimals` — знаків після коми.

```html
<span data-count="100" data-count-suffix="% завантажено">0%</span>
```

Хід рахується від початку картки і завершується на 75 % її тривалості —
остання чверть тримає повний стан, щоб глядач устиг прочитати.

## Наш стиль

Картка стоїть у тій самій смузі, що й стікери, і має читатись як
частина того ж кадру.

| | |
|---|---|
| полотно | градієнт `#FFF → #F6F6F3`, радіус 30 px, тінь `0 20px 52px rgba(17,17,17,.16)` |
| ширина | **поля 110 px з боків**, тобто коробка ~860 px |
| основний текст | Arial/системний, темний `#111111` |
| моноширинний (код, шляхи) | JetBrains Mono / Consolas |
| акцент, смуга, посилання | синій `#0A84FF` — той самий, що в пігулках |
| успіх, «готово» | зелений `#28C840` |
| втрата, помилка | червоний `#FF3B30` — той самий, що в бейджах |
| виділення числа | жовта плашка `#FFE500`, чорний текст |
| службові плашки | сірий `#EFEFEC`, текст `#6B6B6B` |

Темне вікно (`#1A1A1A`) лишається **тільки** для терміналу: там воно
цитує справжню консоль. Решта карток світлі — інакше кадр розвалюється
на дві половини.

### Кегль

Картку дивляться з телефона, у стрічці, часто без звуку. Дрібний текст
там не читається взагалі, а не «читається гірше».

| Що | Розмір при полотні 1080 |
|---|---|
| головне слово, назва | 54 px |
| підсумкова плашка | 44 px |
| заголовок, службовий рядок | 36–40 px |
| дрібні підписи, шкала | 32–34 px |

Менше за 30 px на картці не буває. Якщо текст не влазить — його треба
скоротити, а не зменшити.

### Обʼєм

Плаский колір читається як заглушка. Кожна кольорова поверхня має
градієнт і власну тінь у свій колір:

- смуга й іконки: `linear-gradient(90deg, #4FACFF, #0A84FF)` +
  `0 3px 12px rgba(10,132,255,.4)`
- підсумок-успіх: `#55D96A → #28C840`
- підсумок-втрата: `#FF6B5E → #FF3B30`
- жолоб під смугою: втоплений, `inset 0 2px 4px rgba(17,17,17,.06)`

Сіра тінь під насиченим кольором читається як бруд — тінь завжди
кольору самого елемента.

## Як картка живе в часі

Погана картка зʼявляється готовою і стоїть. Добра **проходить шлях** від
початку речення до кінця:

1. коробка приходить порожньою або майже порожньою
2. під мову наповнюється: рядки, смуга, число
3. наприкінці — підсумок: зелена позначка, готовий стан, висновок

Саме третій крок робить картку висловлюванням, а не ілюстрацією. Він має
збігтися з останнім акцентним словом фрази, а не зʼявитись раніше.

**Підсумок приходить знизу вгору.** Він вирок, а не заголовок: рух угору
читається як «ось до чого це призводить», рух згори вниз — як підпис,
який хтось поклав зверху.

## Що агент вирішує

- який стан картка показує **на початку** речення (порожній? нульовий?)
- що саме росте або відкривається під мову
- чим фраза **закінчується** в кадрі
- скільки рядків: більше пʼяти на картці не читається за три секунди
